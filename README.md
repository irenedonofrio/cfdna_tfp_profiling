# cfdna_tfp_profiling
 
cfDNA transcription-factor profiling pipeline, built on a optimized Griffin (Doebley 2022) fragment/GC correcction. 

 
It has two independent stages that hand off through one small
generated file (gc_correction_manifest.tsv → samples.tsv):
 
1. **GC correction** (`gc_correction/`) — optimized Griffin GC
   correction. Can be run entirely on its own.
2. **Nucleosome profiling** (`nucleosome_profiling/`) —  Reads the manifest produced by stage 1.

A master runner (`run_all.sh`) chains stage 1 → seam → stage 2.


 
## Layout
```
cfdna_tfp_profiling/
├── run_all.sh                 # MASTER: stage 1 -> seam -> stage 2
├── build_stage2_sheet.py      # seam: gc_correction_manifest.tsv -> samples.tsv
├── requirements.txt           # Python deps for a uv venv
├── env/
│   └── environment.yml        # single conda env for the whole pipeline
├── gc_correction/             # STAGE 1
│   ├── run_gc_correction.sh           # stage-1 driver (no scheduler)
│   ├── config_gc.yaml                 # stage-1 params + refs_root
│   ├── stage1_samples.tsv             # YOU EDIT THIS: sample_id <TAB> bam 
│   ├── griffin_GC_counts_prefixsum.py # prefix-sum GC counting
│   └── griffin_GC_bias.py             # GC bias (--no_plots by default)
├── nucleosome_profiling/      # STAGE 2
│   ├── run_profiling.sh               # stage-2 driver (one sample)
│   ├── config.yaml                    # stage-2 params + refs_root + output roots
│   ├── config_helper.py               # the only YAML/sheet reader on the bash side
│   ├── 02_fcc_count.sh                # GC-corrected midpoint (FCC) counting
│   ├── 04_profile_tf_sites.py         # per-chromosome TF profiling
│   ├── 04_merge_and_extract.py        # composite + feature extraction
│   └── samples.tsv                    # GENERATED by the seam (do not hand-edit)
├── refs/                      # bundled reference data (see "References")
└── results/                   # generated outputs (git-ignored)
```
 
## Environment

Environment activation is the **caller's** responsibility — the drivers only
preflight-check the env and fail loudly if it's wrong; they never activate it.

Two options:

1. **conda / micromamba** — one env with the Python stack *and* `gawk` /
   `samtools` / GNU `parallel`. This is the validated pin set.
2. **uv** — Python packages from `requirements.txt`, plus the three CLI tools
   installed from the OS (or a small conda env). Uses current PyPI versions
   and needs **Python ≥ 3.12**.

### conda / micromamba

Install [micromamba](https://mamba.readthedocs.io/en/latest/installation/micromamba-installation.html) (macOS / Linux):

```
"${SHELL}" <(curl -L https://micro.mamba.pm/install.sh)
# or: brew install micromamba
```

Then create and activate the env:

```
micromamba create -f env/environment.yml
micromamba activate tfp
# or, if you already have conda: conda env create -f env/environment.yml && conda activate tfp
```

### uv (Python packages)

Install [uv](https://docs.astral.sh/uv/getting-started/installation/) (macOS / Linux):

```
curl -LsSf https://astral.sh/uv/install.sh | sh
# or: brew install uv
```

Then from the repo root:

```
uv venv --python 3.12 .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
uv pip install -r requirements.txt
```

On some clusters `uv venv --python 3.12` fails with `UnknownIssuer` because uv
downloads a standalone CPython from GitHub and does not trust the site CA.
Use the OS certificate store, or point uv at a Python that is already installed:

```
# 1. prefer the cluster's CA bundle (most common fix)
export UV_NATIVE_TLS=1
# if that is not enough:
# export SSL_CERT_FILE=/etc/ssl/certs/ca-certificates.crt
uv venv --python 3.12 .venv

# 2. or skip the download and use a local 3.12
uv venv --python $(command -v python3.12)
```

`uv` cannot install `gawk`, `samtools`, or GNU `parallel`. Install those next
and keep both the venv *and* the CLI tools on `PATH` when you run the pipeline.

### Command-line tools (required with uv)

The shell drivers call **`gawk`** (not mawk/busybox awk), **`samtools`**, and
**GNU `parallel`**. Debian/Ubuntu often ship `mawk` as `awk`; some systems
install moreutils’ `parallel` instead of GNU parallel. Neither substitute works.

**macOS (Homebrew)**

```
brew install gawk samtools parallel
```

**Debian / Ubuntu**

```
sudo apt-get update
sudo apt-get install -y gawk samtools parallel
# first-time GNU parallel citation prompt:
echo 'will cite' | parallel --citation
```

**Fedora**

```
sudo dnf install -y gawk samtools parallel
```

**RHEL / Rocky / Alma**

```
sudo dnf install -y epel-release
sudo dnf install -y gawk samtools parallel
```

If `samtools` is not in the distro repos, install it (or all three tools) with
conda/micromamba instead:

```
conda install -c conda-forge -c bioconda gawk samtools parallel
```

**Check the right binaries**

```
source .venv/bin/activate    # if using uv
python -c "import numpy, pandas, scipy, pysam, yaml, matplotlib; print('ok')"
command -v gawk samtools parallel
gawk --version | head -1          # GNU Awk …
samtools --version | head -1
parallel --version | head -1      # must say GNU parallel
```

If `parallel --version` prints a one-line usage blurb instead of “GNU
parallel”, you have moreutils — remove it or put GNU parallel first on `PATH`.

## References

The pipeline expects these under `refs/` (paths in both configs are relative to
`refs_root`, which defaults to `../refs`):

- `hg38.fa` **and** `hg38.fa.fai`
- `k100_minus_exclusion_lists.mappable_regions.hg38.bed`
- `hg38.standard.chrom.sizes`
- `genome_GC_frequency/` — per-length background files spanning 15–500 bp,
  named `k100_minus_exclusion_lists.mappable_regions.hg38.<len>bp.GC_frequency.txt` (this is derived from original Griffin's `Ref/` files)
- `TFBS_10000ms/` — TF binding-site BEDs (one per TF), produced by the
  TF-selection stage (see `tfbs_selection/`)

## TF site selection (upstream)

Before the two stages run, `tfbs_selection/` builds the definitive TF list and
the per-TF binding-site BEDs that stage 2 profiles against. It starts from the
GTRD meta-clusters catalogue, keeps only genuine sequence-specific TFs (gated on
CIS-BP), requires ≥10,000 binding sites per TF, and keeps each TF's
strongest-supported sites. This produces the `TFBS_10000ms/` inputs. It's run
once to generate the site files and doesn't need re-running per sample — see
`tfbs_selection/README.md` for the full method and how to regenerate.

## Quick start

Edit `gc_correction/stage1_samples.tsv` (one row per sample: `sample_id <TAB>
/abs/path/to/sample.bam`), then:

```
conda activate tfp
bash run_all.sh                              # all samples, ALL TFs
bash run_all.sh --out-root /scratch/$USER/test   # redirect all outputs (dry-run first)
```

## Use cases

**1. Everything, end to end (all samples)**
```
bash run_all.sh
bash run_all.sh --tfs FOXA1,GRHL2,SPI1       # restrict TFs 
bash run_all.sh --tfs /path/to/tf_list.txt  # or a TF list file (one name per line)
```

**2. GC correction only (all samples)**
```
bash gc_correction/run_gc_correction.sh -c gc_correction/config_gc.yaml
#   --no-resume  recompute even if outputs exist
#   --plots      also emit the QC PDFs
```

**3. Profiling only, all TFs** (reusing GC bias already computed)
```
bash run_all.sh --skip-stage1 --tfs ALL
# or one sample directly:
bash nucleosome_profiling/run_profiling.sh \
    --sample SeCT-26_t2 --config nucleosome_profiling/config.yaml --tfs ALL
```

**4. Profiling only, some TFs**
```
bash nucleosome_profiling/run_profiling.sh \
    --sample SeCT-26_t2 --config nucleosome_profiling/config.yaml \
    --tfs FOXA1,GRHL2,SPI1
# or a TF list file (one name per line):
    --tfs /path/to/tf_list.txt
```

Notes:
- Standalone profiling needs `samples.tsv` (with `gc_bias` + `fcc_dir`). The
  master builds it via the seam; if you ran stage 1 standalone, generate it with
  `build_stage2_sheet.py` (or `run_all.sh --skip-stage1`, which does the seam).
- FCC counting is cached: the first `run_profiling` for a sample runs
  `02_fcc_count.sh`; later `--tfs` runs reuse the FCC. Use `--force-recount`
  only if a counting parameter changed.

## Outputs

Per sample, under `results/`:

```
results/
├── GC_counts/  GC_bias/  gc_correction_manifest.tsv        (stage 1)
└── samples/<sample_id>/
    ├── fcc/                       # sparse per-chromosome FCC
    ├── profiling/composite/       # <TF>_profile.tsv.gz
    ├── logs/
    └── all_TF_features.tsv        # mean/central coverage, amplitude, n_sites
```

## Stage parameters (do not conflate)

Stage 1 and stage 2 deliberately use **different** read filters. Reusing one
stage's parameters in the other breaks byte-identity.

| | map quality | fragment size |
|---|---|---|
| Stage 1 (GC correction) | `map_q = 20` | 15–500 bp |
| Stage 2 (profiling)     | `mapq = 30`  | 120–200 bp |
